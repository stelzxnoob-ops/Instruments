# Token Saver — «токены это бензин»

Принцип: каждый ответ тратит токены на (1) чтение всей переписки, (2) чтение кода,
(3) обдумывание, (4) написание ответа. Длинный чат + максимальное мышление ради
сдвига кнопки на 4px = пустой бак. Подбирай «машину» и «газ» под поездку.

## Шаг 1. Оцени размер задачи (1 строкой, не рассуждай долго)

| Размер | Примеры | Модель («машина») | Effort («газ») |
|---|---|---|---|
| Крошечная | сдвинуть кнопку, текст, цвет, опечатка, одна строка | Haiku — городская малолитражка | low |
| Обычная | фича, экран, endpoint, тесты, рефакторинг одного файла | Sonnet — универсал | medium |
| Сложная | баг, который не понятно где; прод упал; платежи; гонки, миграции данных | Opus — внедорожник | high |
| Огромная | весь проект, архитектура, переписать модуль, многочасовая автономная работа | Fable — экспедиционный фургон | high / xhigh |

`max` — только если пользователь сам попросил. Мышление дольше = дороже, включай его, только когда задача реально требует.

## Шаг 2. Скажи пользователю коротко (только если есть смысл)

Одна-две строки, без лекций:
- Если текущая модель/effort явно больше задачи: «Это мелочь — можно `/model haiku` (или `/effort low`), сэкономишь лимит».
- Если чат длинный (много часов/сжатий контекста), а задача мелкая и не зависит от истории:
  «Лучше в новом чате (`/clear`) — этот чат каждый раз перечитывается целиком».
- Если задача сложная, а модель слабая — наоборот, предложи сильнее. Экономия ≠ скупость.

Не спрашивай разрешения и не жди ответа — если пользователь не переключился, просто делай задачу экономно.

## Шаг 3. Делай экономно

1. **Найди место, не читая всё.** Если есть `graphify-out/graph.json` — сначала
   `graphify query "<что ищем>"`. Иначе `grep -n` по точному слову (класс, текст кнопки, CSS-селектор).
2. **Читай только нужные строки** (`Read` с offset/limit), не файлы целиком. Не перечитывай то, что уже читал в этом чате.
3. **Минимальный дифф.** Правь только то, что просили. Без попутных рефакторингов, «улучшений», новых файлов.
4. **Проверка по размеру:** крошечная правка — без прогона всех тестов (максимум синтаксис/один тест);
   фича — тесты затронутого модуля; сложное — полный прогон.
5. **Без субагентов** для мелочей — каждый субагент заново читает контекст.
6. **Короткий ответ:** что изменено, где (`файл:строка`), что сделать пользователю. Без пересказа процесса.
7. После правки кода в проекте с graphify — `graphify update .` (дёшево, без API).

## Шаг 4. Для длинной работы

- Разбивай на независимые куски; каждый мелкий кусок — можно в отдельном свежем чате.
- Перед `/clear` убедись, что важное закоммичено/записано (CLAUDE.md, заметка), чтобы новый чат не перечитывал историю.
- Повторяющиеся инструкции выноси в CLAUDE.md или скилл, а не повторяй в каждом сообщении.

## Шпаргалка (из видео)

- Кнопку на 4px → Haiku, low, новый чат. «Уже, пока ты спрашивал».
- «На максе проверишь?» → «Отпустите мышку». Max не нужен для мелочей.
- Платежи лежат 3 дня в проде → Opus, high, можно и в длинном чате с контекстом.
- Весь проект / долгая автономная задача → Fable.

## Как подключить в другие проекты

Скилл лежит в `.claude/skills/token-saver/` этого репо (работает здесь автоматически).
Чтобы он был во всех проектах на твоём компьютере/сервере:

```bash
mkdir -p ~/.claude/skills && cp -r .claude/skills/token-saver ~/.claude/skills/
```

Или просто скопируй папку `token-saver` в `.claude/skills/` нового проекта.
Вызов вручную: `/token-saver`.
